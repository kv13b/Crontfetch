Jobs Around Me Guide

The Jobs around me page shows companies near you on a map. This guide follows each thing the page does from the click to the database, and names the file that does each step. Everything runs on free OpenStreetMap data, with no paid API keys.

The big picture

Three layers talk to each other. The React app in the browser calls four routes on the Go API. The API reads and writes Postgres, and only reaches out to public servers when it has to. The colours below are used in every diagram on this page.

Browser (crontfetch-web) Go API (cron-fetch) Postgres Free public servers
OpenStreetMap (OSM)
A free, volunteer-made world map. Every place on it has tags, like office=it and name=Cisco.
Nominatim
OSM's free address search. Turns "Koramangala, Bengaluru" into coordinates. Allows one request per second.
Overpass, Photon
Free public servers that answer "what is near this point?" over OSM data. Often overloaded, so they're our fallback.
.osm.pbf
A compressed download of OSM data for a region. We read it once and keep the offices.
Haversine
The formula for straight-line distance on a sphere. geo.DistanceKm.
Bounding box
A lat/lng rectangle around a point. Cheap to query with an index, then trimmed to a true circle.

How /nearby/places finds offices

This is the part with the most logic. Places.Offices in geo/places.go asks up to three sources in turn and takes the first one that answers. Each source is a small type with the same two methods, Name() and Fetch(), so adding a fourth is one new file.

Flow · importing offices

Filling osm_places from a download

The public map servers were too unreliable to call on every page load: in testing, all four Overpass mirrors timed out for long stretches, and Photon stopped answering after about 60 requests. So we download the map data once and keep the offices in our own table. The Karnataka import takes about 2 seconds and saves 1,838 offices.

Files: cmd/importplaces/main.gogeo/overpass.go (IsOffice, PlaceFromTags)migrations/008_create_osm_places_table.sql

The importer only builds with CGO_ENABLED=0. With cgo on, the PBF library switches to a C zlib that needs a working C compiler. The //go:build !cgo line at the top of the file makes go build ./... skip it in that case, so the rest of the project still builds.

Schema

Database changes

Two new migrations. Apply them by hand in order, like the earlier ones.

companies 007

  • office_addresstext, '' if unset
  • lat, lngdouble, null if unset
  • place_idNominatim's ID
  • geocoded_atwhen it was located

jobs 007

  • last_seen_atrefreshed by each sync
  • closed_atnot set by anything yet

osm_places 008 · new table

  • ide.g. osm:way/456
  • name, kindkind = office type
  • website, address'' when OSM has none
  • lat, lngindexed together

The sync loop (jobsync/db.go) now refreshes last_seen_at when it sees a job again. It still treats a job as new only the first time it's inserted, so Telegram alerts behave exactly as before.

Hands on

Try it locally

PowerShell, from the cron-fetch folder unless noted. Steps 1 and 2 are one-time.

# 1. Database tables
Get-Content migrations\007_add_geo_and_job_status.sql | docker exec -i cron-fetch-postgres-1 psql -U cronfetch -d cronfetch
Get-Content migrations\008_create_osm_places_table.sql | docker exec -i cron-fetch-postgres-1 psql -U cronfetch -d cronfetch

# 2. Import offices (Bangalore is in Karnataka)
curl.exe -L -o karnataka.osm.pbf https://download.openstreetmap.fr/extracts/asia/india/karnataka.osm.pbf
$env:CGO_ENABLED="0"; go run ./cmd/importplaces -file karnataka.osm.pbf

# 3. Run the API, then the app (second terminal, in crontfetch-web)
go run ./cmd/api
npm run dev

# 4. Tests (no network needed)
go test ./internal/geo ./internal/handlers

To pretend you're somewhere else: Chrome DevTools → ⋮ → More tools → Sensors → Location, then Refresh location on the page.

Known gaps

  • The career page isn't always found: in a sample of 25 offices, 10 got a readable job board. Companies on their own career systems (IBM, Atlassian, Walmart) still need the link pasted by hand.
  • Green pins only cover your own tracked companies. osm_places is the start of a shared company directory, but it has no career pages yet.
  • The Go online switch is still UI only. Next steps: a presence table, job matching, then Web Push.
  • jobs.closed_at is never set. The sync only sees jobs that pass a company's filter, so it can't tell "closed" from "no longer matching".
